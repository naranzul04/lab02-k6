3. SLO

Эхний тестээр p95 нь 222.9 ms гарсан. Үүнийг 1.5-аар үржүүлж:
222.9 × 1.5 = 334.35 ms болсон.

Тиймээс SLO-г p95 < 335 ms гэж сонгосон.
Error rate-ийг 1%-аас бага байхаар сонгосон.

4. Threshold

Миний сонгосон SLO нь p95 < 335 ms, error rate < 1% байсан.
5 VU үед p95 нь 272.16 ms гарсан тул PASS болсон.
30 VU үед p95 нь 305.86 ms гарсан тул мөн PASS болсон.
Мөн threshold ажиллаж байгааг шалгахын тулд p95 < 100 ms гэж түр тохируулж үзсэн. Энэ үед p95 нь 342.8 ms гарсан тул FAIL болсон.
Ингэснээр k6 дээр threshold ашиглан PASS болон FAIL үр дүнг шалгаж үзсэн.

5. Дүгнэлт
5 VU үед p95 latency 396.85 ms байсан бөгөөд сонгосон 335 ms-ийн SLO-г хангаагүй. 30 VU үед p95 latency 2.70 секунд болж, гурван түвшнээс хамгийн өндөр latency гарсан. 100 VU үед p95 latency 818.83 ms болсон бөгөөд мөн SLO-г хангаагүй. Ачааллыг 5 VU-ээс 100 VU хүртэл нэмэгдүүлэхэд throughput 6.28 req/s-ээс 107.81 req/s хүртэл өссөн. 30 VU үед latency хамгийн өндөр байсан нь тухайн тестийн үед response time их хэмжээгээр нэмэгдсэнийг харуулж байна. Гурван ачааллын түвшинд error rate 0.00% байсан тул алдааны түвшний SLO бүгд хангагдсан. Энэхүү туршилтаар p90, p95 latency, throughput болон error rate хэмжих аргыг k6 ашиглан туршиж үзсэн. Мөн baseline хэмжилтээс SLO тодорхойлж, threshold ашиглан PASS болон FAIL үр дүнг шалгаж үзсэн. Үр дүнгээс харахад ачаалал нэмэгдэхэд системийн latency тогтвортой бус болж, ялангуяа 30 VU үед мэдэгдэхүйц өссөн байна.
